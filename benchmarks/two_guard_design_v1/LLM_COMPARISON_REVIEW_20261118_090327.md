## 本轮处理

新配置启用 `invalid_hypothesis_mode=unknown_mass`：

- 地图/Track/Schema、假设 ID、全局概率等整体约束不合法时，以明确的 `ModelOutputError` 结束当前方法回合，计失败，继续下一个场景。畸形 JSON 同样处理。公开请求非法、未来时间或配置错误仍作为程序错误中止，避免隐藏实现问题。
- 单条假设的路径、停留或运动约束不合法时，将其概率质量转入 UNKNOWN。保留其他合法路线，**不补连接边、不按成功与否选择路线，也不把剩余合法路线单独归一化**。若原总和在原有 2.5% 容差内但偏离 1，则对所有质量（包括 UNKNOWN）一起缩放，并记录缩放系数。
- 本例合法具体路线概率仍为 0.30、0.27、0.22；UNKNOWN 从 0.08 增至 **0.21**。有路径支撑的质量为 0.79。原模型输出完整保留，新增日志列出拒绝 ID、原因和概率，汇总统计部分拒绝次数。
- 若没有可用具体路线，有观察预算则再观察；预算耗尽则明确计模型输出失败。此类失败不被剔除出已尝试样本，也不会自动重复调用付费 API。

旧配置缺少此开关时仍使用严格校验，原错误可准确重放。更健壮的解码不等于模型原输出有效，也不能把它计为结构校验全通过。

另修正汇总：模型响应即使因校验失败，也应计入 API 时间。本例旧汇总的 `model_seconds=[]` 漏掉了唯一新调用的 3.491 秒；新的读取逻辑从已保存原始响应提取耗时，包括失败响应。模型输出错误另列 `model_output_failures`，与信息不足和程序错误区分。

精确响应多次复用时保留最初的 `original_model_wall_seconds`，避免将一次复用的零新增耗时覆盖为原始模型耗时。复用耗时继续与新 API 延迟分开统计。
