# 双守卫仿真的 LLM 决策研究协议与验证状态

## 研究问题

比较模型的运动事件预测、行为模式推断和直接 Skill 决策，并测量这些能力能否改善配对完整回合的成功率。上一轮的 8 组实验中，纯数值与 DeepSeek Flash 路线预测分别胜 4 局与 3 局，数值观察控制复现全部三场 LLM 胜局。两批历史种子用于机制诊断和离线构样。第一阶段的判定、成本与限制见 [完整配对实验与机制审查](LLM_COMPARISON_REVIEW_20261118_093403.md)。

## 模型与任务

四种离线配置固定为 DeepSeek Flash 的关闭思考和高档思考，以及千问 `qwen3.6-27b` 的关闭思考和开启思考。四种配置使用同一任务输入。请求记录模型名及实际发送的选项。响应保留返回模型标识、最终文本、结束原因、可用用量和首输出时间。DeepSeek 和千问的模型名是服务商提供的标识，请求并未指定独立的、不可变权重快照。千问思考模式采用提示词约束和本地严格解析，关闭思考使用服务端 JSON 模式。该差异在比较格式可靠性时保留。各模式的服务端计时目前未随现有 API 适配器返回。 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) · [千问结构化输出](https://help.aliyun.com/en/model-studio/qwen-structured-output)

2026-11-19 查阅官方文档时，`deepseek-flash` 对应 DeepSeek-V4.1-Flash-1017。回传响应的模型字段仍然是请求中的公开名称，这一版本映射来自文档。 [DeepSeek 模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

- **T1 运动事件预测**沿用原路线协议和轨迹生成器。固定快照将模型特有的既往预测缓存置空，让所有模型从同一公开历史开始。缺少近期、关联成功的双测量 Track 时记为不适用。评分按相同的位置轨迹定义识别平移、停留、移动方向变化、反向和空间进出事件。转向标签对应平移方向，守卫身体朝向和内部巡逻停留原因仍未知。仅在有连续五帧合法目视的窗口内比较，同一快照在每个提前量区间最多取一个窗口。节点事件是进入公开节点的 0.3 米邻域。保留未知和未覆盖质量，报告 Brier 分数范围、可点识别时的 Brier 分数与 Log Loss、决定性预测的 Precision / Recall 和带支持量的时间误差。样本由历史策略的可见性决定，结果限定在这些可评分窗口。
- **T2 行为模式推断**将直接观察事实、推断、依据和不确定性独立记录。校验引用时刻及 JSON 结构。周期、区域交替、重复停留、巡逻阶段和行为变化由审查者结合合法证据评定；当前日志可自动复核证据时刻，语义结论需要定性审查。
- **T3 直接行动**输出一个 Skill ID 或 UNKNOWN，另附简短理由和主要不确定性。Skill 自身编码观察方向、是否用烟和入口；WAIT 为现有单次 Option，无连续控制参数。评分记录格式、合法性、拒答、与记录数值策略的行动差异，以及限定在一个 Option 内的正式裁判反事实。

## 架构与对照

| 方法 | 决策职责 |
| --- | --- |
| D0 | 冻结的纯数值预测、观察判断和优化 |
| D1 | 冻结的原模型配置、区域切片提示词、轨迹生成与同一优化器 |
| D1 matched | 冻结的 D1 优化链和模型配置，加入与 D2/D3 一致的公开场景数据 |
| D1 selected | 若所选直接模型与 M1 不同，增加同完整输入、同模型配置的预测优化对照 |
| D2 | 直接输出 Skill，由既有执行器执行。程序验证格式、合法动作和已公开预算 |
| D3 | 在 D2 基础上检查公开几何中的可行导航路线。已知硬约束违反时按固定顺序尝试合法回掩体或短等，记录建议、拒绝原因和回退。模型调用及界面失败继续保留 |

D1 matched 用原 D1 模型和 API 参数检验扩充公开输入对原架构的影响。D1 selected（如需）让架构比较使用相同模型和 API 参数。直接策略与匹配预测在共同决策边界收到同一结构的完整公开地图、规则、观察历史、自身状态、动作掩码和约束。原 D1 使用之前的地图切片。D1 的模型触发由原信息门与每阶段一次预算控制。D2/D3 在原环境的 Option 边界做直接选择，沿用共同开局探头，之后允许主动观察，并按架构每阶段最多调用 12 次。模型预算耗尽单独记录。各架构仍由同一 Call-and-Return 执行器、资源规则与裁判推进。

仿真逻辑时钟在服务等待期间暂停。计时分为 API 客户端墙钟、完整服务墙钟与本地处理。地图几何已经由官方规划器核对。人工语义标签仍标记待审，结果应按暂定状态解读。地图 Node/Edge 与私有巡逻路线隔离，单次回合的种子、未来样本和裁判内部状态只在仿真和离线评估侧使用。

- **D0 反事实**复现全部 8 个标记终局。6 局标记发生在过门后的继续 Skill，2 局发生在等待。把继续改为一个 WAIT Option，3 个案例活到该 Option 返回。让 6 个替换案例随后恢复 D0 并跑到正式终局，结果仍全部被标记，5 局标记时刻相同，1 局延后 0.02 秒。将两个等待案例改为立即继续也在同一时刻被标记。这个诊断检验的是已经到达这些决策状态后的一次替换，更早的路线、时机和观测选择仍须单独比较。

**T3 直接行动及即时反事实**。36 个固定快照共回放 66 个不同的状态–Skill 组合，全部从对应合法前缀重建。M1 有效行动中 10 次过门返回、8 次探头带回至少两条新目视。M2 分别为 12 次和 6 次。M1 与 D0 共同可评估 33 个状态，其中 17 个动作不同，4 个共同在该 Option 内失败，其余 29 个均活到返回或到达目标。按阶段看，M1 在过门前改变 11/14 个动作，在过门边界改变 1/13 个动作，余下 5 个差异发生在初次探头前。M2 与 D0 共同可评估 31 个状态，其中 16 个动作不同，3 个共同立即失败。M1 与冷启动 D1 的即时失败逐案也相同。D3 对两种模式的有效建议均未触发拒绝或回退。单 Option 回放用于验证行动差异和即时失败机制，整局胜率仍由配对完整回合评估。

两个信息不足的快照说明应把主动探头、继续等待和路线进展分别记录。010 中数值北探得到 1 条新目视，M2 南探得到 26 条，M1 走南入口并完成过门。034 中数值因缺少有效 Track 拒答，M1 的南入口建议完成过门并获得 12 条新目视，M2 等待后未获得新目视。两例只支持对当前 Option 的判断。
