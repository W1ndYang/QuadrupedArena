# 场景版本与视觉 / 物理边界

## 1. 12×8 m 比赛场地（当前可运行比赛）

比赛几何由 `configs/trial_v3.json` 定义，并由后续配置继承。底面平坦，不再使用早期沙地和碎石；保留 4 个高掩体和 4 个低掩体、两个轮换目标位置，以及固定坍塌墙。

`scripts/arena_art.py` 的工业院落外观为同一比赛几何增加混凝土 / 沥青 PBR、倒角表面、接缝、灯光、警示线、围界和外围建筑。装饰范围比 12×8 m 大，但不会自动扩大裁判允许的行走区域。

```bash
bash run.sh --art --headless --preview
bash run.sh --demo --rotating-targets --industrial --headless --preview
```

颜色、法线、粗糙度、光照、相机是视觉属性；碰撞体、裁判射线、路径规划障碍是独立定义。贴图里看起来粗糙或凹凸，不意味着机器人会被真实石块阻挡；当前平地比赛不使用贴图位移或碎石接触动力学。

比赛渲染中有几何掩体，但不由 PhysX 的关节 / 接触动力学推进角色。每个采样点由运动学轨迹设置角色参考位姿，Isaac 负责成像。机载图片确实来自当时的三维场景，不是二维示意图，也不是 AI 生成图片。

## 2. DOCK 07 v1 大地图（审阅版）

配置 `configs/dockyard_v1.json`，生成器为 `dockyard_geometry.py`、`dockyard_art.py`、`dockyard_scene.py`。

| 项目 | v1 参数 / 状态 |
| --- | --- |
| 有效地面尺寸 | 32×24 m，768 m² |
| 内部掩体 | 14 个，8 高 / 6 低 |
| 集装箱 | 3 个贯通通道 + 2 个封闭集装箱 |
| 桥 | 桥面高度 2.2 m，双侧坡道，约 17.74° |
| 桥下空间 | 净高约 2.02 m |
| 固定坍塌 | 20 秒、High3、90°；可分别审阅前后状态 |
| 物理结构 | 主要箱体、板件、坡道具备碰撞；螺栓/条纹等为装饰 |
| 比赛接入标志 | `stage=map_review_only`，`match_integration_ready=false` |

贯通集装箱不是一整个实心盒子：地板、顶板和侧板分别构造，入口留空。桥上 / 桥下同一 xy 可以存在不同 z 层。几何测试验证通行口、净空、坡道以及地面连通性，但不等同于已经验证机器人动力学通行。

```bash
# 静帧：推荐先跑
bash run.sh --dockyard --dockyard-config dockyard_v1.json --headless --preview --no-tour
# 静帧 + 相机绕场巡游 GIF/MP4：不是比赛轨迹
bash run.sh --dockyard --dockyard-config dockyard_v1.json --headless
```

产物包括 `map_design.json`、`geometry_validation.json`、`art_manifest.json`、`review.html`、多个相机 PNG 和坍塌前后 USD；启用巡游还会生成 `dockyard_tour.gif/mp4`。

参照规则来自仓库内 `configs/rules_reference_v04.json`，其内容保持原实验字节不变。无需拥有原作者的实验目录。

## 3. DOCK 07 v2 开发快照

`dockyard_v2.json` 继承 v1，增加港口设备式掩体、泵房、设施细节和部分布局调整。它仍是地图审阅，不是比赛配置。本发布版默认 v1，并保留 v2 的源码供接续；**不声称当前包对 v2 做了完整渲染验收**。

主开发目录在整理发布包时仍有新修改，本仓库是一次独立快照，而非实时同步镜像。继续发布新地图时，应连同对应的生成器、报告代码、几何测试及验收记录一起更新，避免只复制 JSON。

## 4. 为什么不能直接在大地图里重放旧比赛？

同几何换材质 / 光照：可以，`--replay-dir ... --industrial` 不重跑策略。

改变墙体位置、坡道、层高和地图尺寸：不可以直接视作同一比赛。旧轨迹可能穿过新墙、悬空或经过不可达位置；遮挡不同还会改变原本应该获得的观测与命中。

接续工作的最小顺序：

1. 让裁判、导航、渲染共享同一个场景几何来源。
2. 参数化旧代码中 ±6/±4 m 的边界和脚点投影的平地假设。
3. 引入桥面 / 地面层级或 3D 可通行图，定义坡道速度及上下层遮挡。
4. 在新出生点和新目标点上验收路径、倒塌扫掠、可见性和安全距离。
5. 先跑不调用模型的基线和 RGB smoke，再开展独立的新模型实验。

## 5. 历史场景和物理探针

`scene.py`、`terrain.py`、`demo.py` 保留早期沙地 / 碎石 / 起伏场地能力，不是当前比赛默认设置。早期 `--demo` 需要显式提供已经生成的 `--scene /path/to/arena_rough.usda`；不再指向原机的固定时间戳目录。

`--embodied-probe` 是 Go2-W 关节驱动、物理刚体与相机的小型独立工程实验，不是比赛主线。它需要先生成 Go2-W 的转换 USD；无需把该探针结果外推为“LLM 已能控制动力学比赛”。

`--robot go2` 依赖原工程定制 Unitree RL Lab 中的 `UNITREE_GO2_CFG`，该依赖没有整体打包。若研究目标仅是场景/规则/视觉规划，不应从此历史入口开始。
