# Breach Arena（突破攻防）

**一个新的、独立的对抗游戏**：LLM 指挥的四足进攻一个固定目标，人（脚本机器人或真人）防守。规则版本 `breach-v1.0`，决策协议 `breach-protocol-v1`，地图格式 `breach-map-v1`。2026-11-08 首版。

人可以选择两种打法，四足各有一种对策：

- **守点**：守在目标上，或站在附近的远守位。四足的对策是**封烟强冲**：从隐蔽的投烟点把唯一一颗烟扔到人的视线上，再冲点。
- **出击**：离开目标去找四足。四足的对策是**诱敌迂回**：先在一侧露面，再在人看不到的地方转移，等人走远后从另一扇门突入。

对策用错就会输：不放烟去绕门，打不过守点的人；在出击者那一侧投烟，会被出击者看到。所以四足要先从合法观测里判断人是在守还是在出击。演示时可以打两局：第一局人自由选择打法，第二局换另一种打法，看四足能不能读出来并换对策。

> 本模块只有 CPU 运动学裁判、俯视回放和 pygame 真人客户端，**还没有接 Isaac 渲染**，也**还没有用真实付费模型跑过**。大模型这条链路目前只用离线替身跑通过，替身按规则基线出决策，见“已知限制”。

## 与仓库其他内容的隔离

| 内容 | 位置 | 和本模块的关系 |
| --- | --- | --- |
| 历史累计占点赛制（2026-10） | `scripts/`、`configs/` | 不导入、不共用配置 |
| 固定目标 v0.4.1 可复现发布 | `benchmarks/fixed_goal_v041/` | 不导入；规则数值参考过，但在这里重新实现 |
| 固定目标 v0.5 展示包 | `benchmarks/fixed_goal_v05_showcase/` | 只是展示数据，不导入 |
| **Breach Arena（本模块）** | `breach_arena/` | 自带裁判、寻路、技能、机器人、地图、协议、回放和测试 |

隔离是靠下面几条做到的，`tests/test_isolation.py` 会逐项检查：

- 只依赖标准库、numpy 和 matplotlib；真人客户端另外需要可选的 pygame。不导入 `scripts/` 或 `benchmarks/` 里的任何模块，也不读它们的文件。
- 规则（`rules.json`）、地图（`maps/BA-*.json`）和协议都有自己的版本号，加载时会校验。旧赛制的 `trial_config.json` 和 `layouts.json` 在这里不能用，这里的地图也不要拿到旧裁判里用。
- 产物统一写到 `.arena-workspace/breach_arena/runs/<时间戳>_…/`，这个目录已被 Git 忽略，也可以用 `ARENA_WORKSPACE` 改到别处。
- 结果不要和 v0.4.1、v0.5 混在一起比较：感知、技能和决策时序都不同，差异见 [RULES.md](RULES.md)。

## 5 分钟上手（CPU，无 API、无 GPU）

在仓库根目录运行（参考环境是 Python 3.11 加 `requirements-cpu.txt`，不需要新增依赖）：

```bash
# 32 个测试，约 20 秒：规则、视线、烟雾、异步决策、地图一致性、打法对策矩阵、隔离
python -m unittest discover -s breach_arena/tests -t .

# 打法对策矩阵：每一格都过真实裁判，结果是确定的
python -m breach_arena matrix --map BA-1

# 单局：规则基线四足 vs 出击机器人，保存回放和离线 HTML 播放器
python -m breach_arena play --map BA-1 --human hunt

# 两局：第一局守点、第二局出击；四足带着上一局的合法摘要进入下一局
python -m breach_arena series --map BA-1 --humans hold,hunt

# 走一遍大模型链路（离线替身，不联网、不计费），每次决策固定延迟 1.5 s，比赛不暂停
python -m breach_arena series --map BA-1 --humans hold,hunt --quad fake-llm --fake-delay 1.5
```

每局会写出三个文件：

- `roundN.viewer.html`：离线播放器，用浏览器直接打开，可以拖动时间、看双方路径和锁定线，并按时间对照四足的每次决策；
- `roundN.replay.json.gz`：完整的逐帧状态和事件；
- `roundN.summary.json`：结果和决策摘要。

人方机器人有这几种：

- `hold`：贴点守；
- `standoff:S_NE`：站在指定远守位守，可用的远守位见地图；
- `hunt`：出击，丢失目标 10 s 后回防；
- `hunt:4`：谨慎出击，丢失 4 s 就回防。

## 接入大模型（比赛不暂停）

```bash
export DEEPSEEK_API_KEY=...        # 或者用 --key-file 指定一个本地文件
python -m breach_arena series --map BA-1 --humans hold,hunt \
  --quad llm --llm-config breach_arena/llm/presets/deepseek.json --timing virtual
```

- 接口是 OpenAI 兼容的 `chat/completions`，只用标准库实现：不重试、不跟随重定向，日志里的密钥一律替换掉。`presets/` 里的 DeepSeek 和 Qwen 配置只是示例，模型名和价格以服务商当时公布的为准。
- 决策时序有四种，详见 [PROTOCOL.md](PROTOCOL.md#时序)：

  | 模式 | 怎么跑 | 用途 |
  | --- | --- | --- |
  | `virtual` | 不暂停；模型实际用了多少秒，比赛就在这期间推进多少秒；没有请求时全速跑 | 无头实验的默认值 |
  | `realtime` | 比赛按墙钟走 | 真人对战 |
  | `fixed:S` | 每次决策固定延迟 S 秒 | 测试 |
  | `pause` | 调用期间比赛暂停 | 只用于和旧研究对照 |

- 提示词里有公开规则、公开地图和技能表，可以用 `python -m breach_arena prompt --map BA-1` 查看。另有两个实验开关：`--hints none|routes|full` 控制给不给路线提示和烟点提示，`--no-strategy` 去掉“守点吃烟、出击吃迂回”那一段提示。
- 每次请求和返回都保存在 `roundN_api/`，包括系统提示词、精简后的合法观测包、原始返回文本、用时和 token。
- 模型只能看到四足的合法信息：当前看得见的对手、最多 4 s 的记忆、合法目击记录、自己的状态、烟雾和技能执行结果。`tests/test_protocol.py` 会逐包核对：只要裁判判定四足看不到人，模型收到的包里就不会有人的位置。

## 真人对战（pygame）

```bash
python -m pip install -r breach_arena/requirements-live.txt
python -m breach_arena live --map BA-1 --rounds 2                 # 四足用规则基线
python -m breach_arena live --map BA-1 --quad llm --llm-config breach_arena/llm/presets/deepseek.json
```

- 你扮演人。WASD 或方向键移动，鼠标瞄准，按住左键或空格开火。
- **辅助瞄准**：开火时，如果四足在你合法可见范围内，且在鼠标方向 ±20° 以内，身体会自动跟住它。命中仍要求你站定、连续锁住 1 s。
- 画面里只画你合法能看到的东西：四足只在可见时显示，丢失后留一个最后位置的残影。四足的计划和裁判内部状态不会显示给你。
- 比赛按真实时间推进，模型的决策在后台线程里返回，不会暂停比赛。

## 当前结果（本提交、确定性，可用 `matrix` 复现）

下面每一格都是真实裁判跑出来的。“规则”指读人再选对策的规则基线 `ReadAndCounter`；“脚本”指强制执行某一种打法，用来检验“打法用错就会输”。

**BA-1 三门庭院（推荐用于演示）：12/12 与设计一致**

| 人 | 四足 | 结果 | 说明 |
| --- | --- | --- | --- |
| 守点 | 规则：读出守点 → 北窗投烟、烟落在冲点路线上 | 四足 12.9 s 到点 | 封烟强冲赢守点 |
| 远守东北 / 西南 | 规则 | 四足 12.9 s 到点 | 路径烟同时遮住远守位和目标 |
| 出击 | 规则：西广场露面 → 北走廊转移 → 北门突袭 | 四足 12.3 s 到点 | 诱敌迂回赢出击 |
| 谨慎出击（丢失 4 s 即回防） | 规则：同上 | **人 12.3 s 标记** | 迂回是一场赌：人回得早，四足就输 |
| 守点 | 脚本：不放烟绕北门 | 人 9.0 s 标记 | 守点赢不放烟的迂回 |
| 守点 | 脚本：露面后迂回 | 人 13.4 s 标记 | 人不追出来，诱敌就落空 |
| 出击 | 脚本：从西窗（出击者那一侧）投烟 | 人 10.8 s 标记 | 出击赢同侧封烟 |
| 远守东北 | 脚本：北窗投烟到目标上 | 人 9.3 s 标记 | 扔在目标上的烟挡不住远守 |
| 远守东北 | 脚本：北窗投烟到路线上 (8.6, 2.2) | 四足 9.8 s 到点 | 同一个投烟点，只是烟落点不同 |
| 远守西南 / 守点 | 脚本：南窗投烟到目标上 | 人标记 / 四足到点 | 目标烟只对贴点守有效 |

**BA-2 低墙广场（实验图）：8/8 与当前记录一致**。规则基线对守点、两个远守位和出击都能到点：它按目击到的站位计算烟落点。但固定的诱敌迂回打不过出击者，因为广场太开阔，转移途中就会被看见。这一点和静态检查给出的“人走出 5 m 就能迂回”不一致，详见 [MAPS.md](MAPS.md)。

## 已知限制

1. **抽象层级**：和仓库里早期的固定目标原型一样，这里只是有速度、加速度和转向限制的参考运动，没有接触动力学，没有步态策略，也没有 Isaac 画面。视线只用代表点之间的连线判断（四足 0.40 m，人眼 1.05 m），不算身体的可见面积。
2. **烟雾很强**：静态检查发现，每个投烟点都有一个“通吃”落点（落在最后一段冲点路线上），能同时挡住贴点和所有远守位。也就是说，人如果原地不动，挡不住一颗放对位置的烟。人真正的反制是动起来，或者盯住、抢占投烟点，也就是出击。所以本作是“守点 / 出击 × 封烟 / 迂回”的循环，而不是让四足去分辨远守位的具体位置。
3. **迂回是赌时机**：BA-1 上，出击者大约要走出西门之后突袭才安全；谨慎出击的人（丢失 4 s 即回防）能反制迂回。BA-2 上，固定的迂回路线在开阔广场里会被看见。
4. **人方机器人很简单**：只是位置加反应时间的脚本，不会预判，不会听声音，也不会配合烟雾变换站位。用真人测试会比用机器人更能说明问题。pygame 客户端目前只做过无头冒烟测试，还没有真人试玩过。
5. **大模型链路**：协议、校验、异步时序和日志都用离线替身测过，但本提交没有调用过任何真实服务商，也没有做过费用和延迟统计。

后续可以做的事：用真人试玩 BA-1 的两局演示；再用真实模型分别跑 `virtual` 和 `realtime` 模式；把回放接到 Isaac 渲染。
